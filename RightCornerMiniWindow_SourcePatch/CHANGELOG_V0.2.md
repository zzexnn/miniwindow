# V0.2.0-test 修复与验收

适配目标：HyperOS 4.0 平板 / LSPosed API 102+。
固定上游：mikudayoooooooo/HyperSideBar@e45661e0f2f51bac84d00f954ad2da0edf1c24e3。

## 已修改

- 移除右下角输入路径和新菜单的竖屏限制；保留上游 CornerTrigger 默认行为，只有新路径显式允许横屏。
- 使用实际显示区域，避免宿主资源尺寸与触摸原始坐标不同。
- 起手位置只在 DOWN 决定；MOVE 跨过半屏不再取消。
- 在接收器主线程内立即显示菜单，不再排队到 UP 后被撤销。
- SystemUI 通过带认证的响应确认当前版本执行端可接收后，才允许同进程 pilfer；执行端没有所有权证据不显示可启动菜单。
- PackageReady 后补挂宿主通道，避免只等 Application.attach 导致注册永远错过；新增通道随热重载释放。
- 修正 Native C 配置/总闸的旧包名媒体目录，保留上游 native hook 安装、匹配和恢复机制。
- ConfigSync 在 attach 期间保存可用的原始 Context；认证令牌通过现有 Binder 配置服务拉取，不进入公共配置广播，后续普通同步保留已拉取令牌。
- 诊断区分别显示框架连接、当前版本 SystemUI / 安全中心实际响应、输入事件计数、执行端就绪和窗口错误；有手动菜单测试、运行日志和导出报告。
- 设置页处理系统安全边距，返回按钮使用至少 48dp 的点击区域。应用列表、诊断、日志均有页面内系统返回处理。
- 灵敏度提供 8/12/18dp 三档，输入两端共用阈值；收藏按用户顺序取前五。推荐不再排除收藏导致不足五项。
- 菜单旋转、取消、多指、新手势和超时均清理；预览不会启动应用。窗口失败记录类型与异常，system uid 宿主才允许尝试旧式系统窗口。
- CI 执行完整上游单元测试，加上 8 个新回归用例，并检查 APK 的 LSPosed 元数据和所有 arm64 动态库的 16KB ELF/ZIP 对齐。
- 当前构建使用 CI 临时调试签名；不上传签名私钥。测试包出现签名冲突时需卸载旧版再装，正式发布应配置仓库私密签名。

## 真机测试

1. 安装 V0.2.0-test；若系统提示签名冲突，先卸载旧测试包再安装（V0.1 CI 未保存调试私钥，无法复原其签名）。
2. LSPosed 启用模块，保留 securitycenter / home / systemui 三个作用域；关闭再启用模块后重启整机。
3. 打开模块，进入诊断，点“重新检测并同步配置”。等待约 10 秒再测一次。应看到当前版本两个 Java 宿主响应，输入监视器=true。OS4 的桌面可能为纯 Native，不把桌面 Java 无响应误判为失活。
4. 点“测试宿主菜单”：右下角应显示 5 秒后关闭。若失败，诊断会显示窗口类型及权限/Token 异常。
5. 设置五个收藏并拖动排序；系统返回键应回到设置页，顶部“返回”应位于状态栏下方。
6. 在横屏、竖屏分别从右下角向左上斜滑并保持手指不松开。先测试推荐松手，再滑入文件夹、滑回收藏应用后松手；第六格返回应原位切回推荐。
7. 测试竖直上滑、普通返回、多指、取消以及关闭总开关后系统触摸是否正常。
8. 如仍失败，连续尝试 3 次后立即导出自检报告。报告能区分无注入、监视器无事件、执行端未就绪、角度/距离拒绝、窗口创建失败、原生小窗启动失败。

## 证据边界

构建与单元测试通过不能证明 目标平板真机手势已经修好。当前环境没有该设备和 ADB 连接，无法读取其 LSPosed 加载日志或确认 ROM 小窗私有 API。上述行为仍需用户设备验收；不得把“作用域已勾选”“框架已连接”“输入监视器创建成功”合并为“全链路可用”。
